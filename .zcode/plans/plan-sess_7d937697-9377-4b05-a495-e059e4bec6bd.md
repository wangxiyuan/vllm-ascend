### 背景

label 解析链是：`pr_test.yaml` 的 recommend-tests-from-coverage / ready-all 扫描 → `select_tests.py` 按目录路由到逻辑分区 → `test_config.yaml` 的 `partition:` 把分区映射到具体 runner label → `_selected_tests.yaml` 的 `runs-on: ${{ matrix.group.runner }}`。所以改动集中在 `select_tests.py` 和配置文件，workflow yaml 不用动。

根据你的澄清：`linux-aarch64-a3-2-/4-/8-` 这类通用 label 本身就是 560t/752t 混合的随机池，所以"不含精度用例 → 随机"就是现状，无需改动；只需要在**选中了精度用例**或 **ready-all 全量**时，把通用 A3 分区改指到 560t 的 `800i` label。

### 改动

1. **`.github/workflows/scripts/runner_label.json`**
   - 新增 `linux-aarch64-a3-16-` 条目（chip `a3`，npu_num 16，image_tag/csrc_cache_target 与现有 A3 条目相同），作为 16 卡的混合池 label。保留现有 `linux-aarch64-a3-800t-16`（weekly/nightly 等 workflow 仍在用）。

2. **`.github/actionlint.yaml`**
   - 在允许的 runs-on label 列表中加入 `linux-aarch64-a3-16-`。

3. **`.github/workflows/scripts/test_config.yaml`**
   - `partition:` 中 `a3-16` 的 `runner_label` 由 `linux-aarch64-a3-800t-16` 改为 `linux-aarch64-a3-16-`（不区分 752/560，按你的要求）。
   - 在文件头部注释补充说明这一调度策略。

4. **`.github/workflows/scripts/select_tests.py`**
   - 新增常量：精度用例识别正则 `_ACCURACY_TEST_PATTERN = re.compile(r"(accuracy|precision)")`（匹配测试文件路径），以及通用 label → 560t label 的映射 `{"linux-aarch64-a3-2-": "linux-aarch64-a3-800i-2", "linux-aarch64-a3-4-": "linux-aarch64-a3-800i-4", "linux-aarch64-a3-8-": "linux-aarch64-a3-800i-8"}`。
   - 新增函数 `_prefer_560t_partitions(partition_config)`：返回一份拷贝，把上述映射中的通用 label 替换为对应 800i label（count 不变，800i 与通用分区的 count 本来就一致：2/2）。
   - 在 `main()` 中、`_apply_pinned_routes`（846 行）之后、`--runner-label-override` 之前：当 `args.all_tests`（ready-all）为真，或选中的用例中存在路径匹配精度正则的文件时，调用该函数。其余情况不动，维持混合池随机调度。
   - pinned_routes 已钉到 `a3-800i-*` 的精度用例不受影响（本来就在 560t）。

5. **单元测试**
   - 找到 `tests/ut/` 下现有的 select_tests 测试文件，新增用例覆盖三种场景：选中精度用例时 label 变为 800i；未选中精度用例时保持通用 label；`--all-tests` 时 label 变为 800i。同时覆盖 `a3-16` 分区解析到新 label。
